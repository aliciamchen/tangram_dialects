# Data, statistics and the report layer

## Datasets

Everything is keyed by a dataset name: `--dataset` on a script, else the `DATASET` environment variable, else `full`. `make` passes `DATASET` to every step (`make test DATASET=smoke`). The layout is defined in `preprocessing/dataset_paths.py`, mirrored in `stats/config.R` (`use_dataset()`; change both together) and described for readers, with every column, in `data/README.md`; describe it nowhere else. The article's figures are assembled from the panels in `results/plots/` in Illustrator, and the exports the manuscript includes are in the top-level `figures/paper_files/`, not per dataset. `results/` is committed, so `git diff` on it is the regression check for any analysis change; a dataset other than `full` writes its results to `data/<name>/results/`, so a trial run never touches it; `data/full/` is local and stays so until the RefBank release; the pilot dataset and its SI notebook are at the git tag `pilot-archive`. Everything identifiable (`experiment/data/`, `experiment/pilot_data/`, `data/runs/`, `data/payments/`, `backups/`) is gitignored.

Inputs a dataset directory may hold, each read at the step named:

| File | Read by | Meaning |
|------|---------|---------|
| `runs.txt` | combine | Export timestamps to stack, one per line, `#` comments allowed. Exports are cumulative snapshots of one server, so a later export of the same server replaces an earlier one; `data/full/runs.txt` names the final export of each of its 31 server periods, and `make final-exports` verifies that set |
| `exclude_games.txt` | combine | Game ids dropped with every dependent row: rehearsal games and games with a repeat participant. `make payments` ignores it, so those players are still paid and blocklisted |
| `participant_exclusions.csv` | preprocess | `playerId,reason`, reason required, unknown ids refused. Removes the player's messages from `messages.csv` and both utterance files, so every measure excludes them; flags `excluded`/`exclusionReason` on their rows and on the rows of listeners they spoke to in `trials.csv` and `social_guesses.csv`; blanks their `exitSurvey_*` columns in `players.csv` (the answers stay in `raw/`). `responseOpportunity` is left as computed |
| `technical_exclusions.csv` | preprocess (R reports it) | `gameId,playerId,roundId,outcome,reason`, `outcome` one of `referential`, `social`, `both`, reason required: documented technical failures, whose `correct` becomes missing rather than 0 |
| `integrity_exceptions.csv` | integrity suite | `invariant,gameId,playerId,roundId,reason`: the cases where an invariant does not hold. The tests require the cases they find to equal the documented ones, so a new case fails and so does a documented case that disappears. It records data loss and instrumentation races, never analytic choices |
| `payment_adjustments.csv` | `make payments` | See `.claude/rules/operations.md` |

Outputs worth knowing: `raw/manifest.json` (runs combined, games filtered and excluded, dropout count); `tables/dropouts.csv` (player records with no real game: quiz failures, lobby timeouts and overflow arrivals, with `condition` and `tangramSet` from the batch's treatment); and the sidecar `tables/speaker_utterances_filtered.source.json` (below).

## Pipeline steps

`make data test estimates report`, each verb a group of the finer targets below (`make help` lists them), or `make smoke ZIP=<zip>` to run the pipeline on a throwaway dataset `smoke` (it clears `data/smoke/` itself; leave it afterwards, since the agent hook blocks recursive deletes; the block-count checks fail for TEST_MODE games). The `rebuild-dataset` skill is the procedure for `full`.

- **Extract** (`extract_run.py <zip>`) unzips into `data/runs/<ts>/raw/`, drops `SENSITIVE_COLUMNS` from `player.csv`, redacts 24-hex Prolific-id tokens in every text cell, and registers the timestamp in `runs.txt` unless `--no-register`. It is deterministic.
- **Combine** (`combine_runs.py --dataset <name>`) unions the registered exports on record id, keeping the newest version of each record, drops excluded games, removes player records of games that never started, and writes `raw/` with its manifest and `tables/dropouts.csv`.
- **Process** (`process_data.py`) runs four sub-steps. *Preprocess* (`preprocessing.py`) writes `data/<name>/tables/`, honors the exclusion files, codes the accuracy outcomes and adds the analysis columns (both below), and prints, per column, how many JSON values it could not parse (silence means all parsed). *Filter* (`filter_nonreferential.py`, see `.claude/rules/message-filter.md`) labels speaker messages and writes `speaker_utterances_filtered.csv`; `--skip-filter` falls back to the unfiltered file with a warning. *Measures* (`compute_measures.py`, `--skip-measures` to omit, `make measures` to run alone) writes `data/<name>/measures/`: the embeddings, the adjacent, final-window pairwise and block-by-block similarity tables, the pairwise and block tables scored again by content-word Jaccard in the same row order (`*_jaccard.csv`, NaN where a side has no content words), each speaker's Phase 1 to Phase 2 similarity, and the per-description properties (concreteness, word frequency, lexical uniqueness). *Model inputs* (`build_model_inputs.py`, `--skip-model-inputs` to omit, `make model-inputs` to run alone) writes `data/<name>/model_inputs/`: `within_group_block_means.csv` and its `_jaccard` twin (one mean per original group, tangram and block over the within-group pairs, the H3b unit), `block_similarity_means.csv` and its twin (one mean per game, block and pair type, within or between original groups, the descriptive specificity trajectory the figures draw), `final_phase_properties.csv` (each speaker's final description of each tangram in each phase with the H3c measures) and `ingroup_advantage.csv` (per listener, Phase 2 accuracy with an in-group speaker minus with an out-group speaker). Every model input keeps all phases and conditions; a model restricts when it is fit.
- **Test** (`make test`) runs the integrity suite on the active dataset, the Python unit tests, and `Rscript stats/tests/run_all.R`. Besides the game-as-designed invariants it rebuilds both utterance files from `messages.csv` and the classifier labels, recomputes every row of the pairwise, block and adjacent similarity tables from the utterance file and `embeddings.npy`, and reconciles the processed tables with `raw/` and its `manifest.json`, so a measure that no longer follows from the code fails here.

**Filtered utterances are tied to `messages.csv`.** `apply` writes the sidecar with the sha256 and row count of the `messages.csv` it read. `compute_measures.py` and `config.R` refuse a filtered file whose sidecar is missing or stale, and `preprocessing.py` deletes a stale filtered file when it rewrites `messages.csv`. `dataset_paths.filtered_utterances_status()` is the one check. Never copy a filtered file between datasets.

**Caches are keyed to their inputs.** All in `data/<name>/cache/`: `group_specificity.R` stores a hash of the pairwise data beside `gs_results_<speaker structure>.rds` and recomputes when it differs (several minutes); `bayes_factors.R` names each brms fit in `cache/bayes_factors/` by a hash of data and formula; and `primary/h4.R` saves its two fitted models in `cache/fits/` for `robustness.R` and `bayes_factors.R`, which stop with the script to run when a fit is absent. A rebuild that changes the pairwise tables refits on the next `make estimates`.

## Definitions that are easy to get wrong

- **`allGroupsPaired`** on both block tables is 1 where every original group has two speakers who have described that tangram by that block, the preregistered start rule for group specificity; it is 0 in the first block of each phase and where a removed or reassigned speaker leaves a group with one describer. "Every original group" means every group with a description of that tangram in the phase so far, so a group that has not described it does not hold the flag at 0. The block-by-block specificity trajectory (`checks/specificity_trajectory.R`, through `block_specificity_table()` in `R/group_specificity.R`) fits the per-game model to the rows `specificity_eligible()` (`R/prepare.R`) keeps; the group-specificity figure uses every row, omitting only a condition's cells with fewer than `MIN_GAMES` (10) contributing games, which removes the block 7 within-group pairs that games short a member produce.
- **Accuracy denominators** are eligible listener response opportunities, not submitted answers: `hasSpeakerMessage` and `responseOpportunity` on `trials.csv`, and one row per eligible Phase 2 listener in `social_guesses.csv`. A correct on-time answer is 1; an incorrect answer, a timeout and a late arrival are 0. Lateness is `lateClick` and `lateSocialGuess`, set by the server from its deadline snapshot; `preprocessing.py` reapplies `idle.js`'s rule from `clicked_at_deadline` and `social_guess_at_deadline` for answers that arrived after Feedback ended. The outcome is coded once, by `preprocessing.py`, as `correct` (1, 0 or missing) with `onTime` on both tables, and the R helpers read it.
- **Analysis columns.** `trials.csv`, `messages.csv`, both utterance files and `social_guesses.csv` carry `condition`, `block` (the 1-indexed block within the phase, the paper's numbering; `blockNum` is the export's 0-indexed count) and `gameBlock` (counted across the game with each game's own Phase 1 length, so Phase 2 of a 6 + 6 game starts at 7). Figures and models read these and never join the condition or add one to a block themselves.
- **Attrition facts** are columns too: `removed`, `removalReason` (idle, low accuracy, group disbanded, insufficient groups, game terminated, other; empty for a player who finished) and `removedNoFault` on `players.csv`, and `ranToCompletion` (two or more original groups viable at the end) and `completeNine` (ran to completion with all nine players) on `games.csv`, coded by `add_removal_columns()` and `add_completion_columns()` in `preprocessing.py`. `R/attrition.R`, `report/descriptives.py` and the figures read them and never recode `isActive` or `exitReason`.
- **Two clocks.** Participant-clock columns (`selectionRenderedAt`, `tangramSelectedAt`, `clickedAt`, `socialGuessSelectedAt`, `composeStartedAt`) are valid only within one participant, because browser clocks differ by up to minutes; the derived `selectionRt`, `socialGuessRt` and `composeMs` are within-participant differences and safe. Server-clock columns (`selectionStartedAt`, `selectionEndedAt`, `selectionDurationMs` from `stage.csv`, and any raw attribute's `*LastChangedAt`) are comparable across everyone. `tangramSelectedAt` is when the participant chose and is the only response time comparable across conditions; `clickedAt` is when the choice reached the server, which in the social conditions is the submit time.
- **Connection and engagement records** were added during the September 2026 sessions (the connection log from 2026-09-25), so every such field is optional in `preprocessing.py` and an export that predates one must keep processing. An `offline` event is written on reconnect, paired with its `online`; a participant who never came back leaves no record. `players.csv` carries the counts (`tabHidden*`, `offline*`, `resizeCount`, `disconnect*`, `pageLoadCount`, `reloadCount`, the `*Truncated` flags); the event lists stay in `raw/player.csv`; the raw user agent is stripped at extraction. `disconnect*` count only the part of each drop inside the player's game window, which `summarize_connection()` moves onto the participant's clock with `participant_clock_offsets()` (the median of `selectionRenderedAt` minus `selectionStartedAt` over their trials), the one place the pipeline relates the two clocks.
- **The per-game model** in `R/group_specificity.R` is the preregistered one, `similarity ~ sameGroup + (1 | target) + (1 | speakerPair)`, and the only one the scripts fit; its name is part of the cache key and filename. The multiple-membership speaker structure it was chosen against lives with its simulation in `simulations/` and no analysis script uses it.
- **Convention-formation checks** (`convention_check_data()`) keep all four conditions for description but fit the trend models on `H12_CONDITIONS`; they inform H1 and H2 and gate nothing.
- **Groups.** `originalGroup` persists for the whole game; `currentGroup` changes per trial in mixed Phase 2, where chat names are masked, so `senderName` in `messages.csv` is uninformative there while `senderId` stays valid. The reshuffle guarantees mixing only in rounds where every group is a trio.
- **Repeat participation** is checked by `make payments` (`repeats.csv`), not by the pipeline; a game with a player who had played a full game in an earlier session is excluded whole through `exclude_games.txt`.

## The analysis scripts

`stats/<family>/<name>.R`, one per analysis, where the family is `checks`, `primary` or `secondary`, or `exploratory` for a comparison the preregistration does not name that the author has asked to report (it writes estimates for the figures and, so far, no macros). Each sources `stats/config.R` (paths, constants, every helper in `stats/R/`), loads the tables with `load_tables()`, fits its models, prints their summaries and support sentences, and writes its estimates with `write_estimates(df, "<family>/<name>", source = ...)` to `results/estimates/<family>/<name>.csv` (a script with several tables adds a suffix: `primary/h4_social_components.csv`). The rows follow one shape, described in `stats/R/tidy.R`: `analysis`, `kind` (coefficient, contrast, trend or test), `term`, `estimate`, `std_error`, `statistic`, `df`, `lower`, `upper` (the 95% interval: emmeans's for a contrast or a trend, Wald for a logistic coefficient, the t interval on the coefficient's degrees of freedom otherwise), `p_value`, odds ratios for logistic coefficients, and `n_obs`, `n_games` and `random_effects`. A block effect in a condition-by-block model is written as the `emtrends(~ 1)` slope averaged over conditions (`tidy_trends()`), never as the `blockNum_c` coefficient, which under treatment coding is the reference condition's slope. A comparison the data cannot support writes no row, so it gets no macro and fails loudly in LaTeX rather than reading as a result. A script that needs another's estimates reads them with `require_estimates()`, which names the script to run first; `primary/group_specificity.R` writes the per-game estimates every game-level regression reads (`gs_wide()` turns them into one row per game), so nothing is fit twice. A model that more than one script fits has one fitter in `stats/R/` (`fit_h12()`, `fit_h3a()`, `fit_h3b()`, `fit_h3c()`), so a rerun in `robustness.R` cannot drift from the primary test. `R/prepare.R` only subsets, sets factor levels, centers and adds the reporting flags; the coded outcome, the attrition facts and the model inputs come from the pipeline. The helpers have `stopifnot` tests in `stats/tests/`, one file per helper; the scripts themselves are checked by comparing `results/` before and after a change (`git diff`).

The Makefile derives the estimates targets from the scripts in `stats/<family>/` and lists, per table, the data and estimates it depends on (a new script needs one such line), and a pattern rule runs `Rscript stats/<family>/<name>.R`, so `make estimates` fits only what is out of date, everything after an edit to the shared R code, and `make estimates -j` runs independent scripts in parallel (the manifest update holds a lock). Every estimates table and macro file records the git commit it was written at, with `-dirty` when a tracked file outside `results/` had uncommitted changes; commit the code first, run, then commit `results/` on its own, so that the recorded commit is clean and names the code. `BAYES_FACTORS` (`auto`, `always`, `never`) governs `primary/bayes_factors.R`; with `never` the script leaves without touching `primary/bayes_factors.csv`, so the Bayes factors of the last real run stay in place. Each Bayes factor is the Savage-Dickey density ratio of the tested coefficient from the brms fit of the full model; one whose fit or density estimate warned is recorded with the warning and never becomes a macro.

## The report layer and the manuscript

| Writer | Reads | Writes |
|--------|-------|--------|
| `report/inferential.py` (`make inferential`) | `results/estimates/` | the inferential macros `results/macros/<checks,primary,secondary>.tex`, one family per file |
| `report/descriptives.py` (`make descriptives`) | the processed tables, the measures and `estimates/primary/group_specificity.csv` | the descriptive macros `<overview,exploratory,survey>.tex` |
| `report/figures/<name>.py` (`make figures`) | the model inputs and the estimates | `results/plots/<name>.pdf` |

Statistics reach a manuscript only as `\newcommand` macros (letters-only names, a header naming the writer and a second naming the git commit and dataset, never hand-edited), written by `write_stats_tex()` in `report/stats_tex.py`, which also holds every formatting rule (`fmt_stat`, `fmt_pval`, `fmt_count`, `fmt_bf`, `condition_macro_name`); one writer per file, and `check_unique_names()` refuses a name defined in two files. The formatter reads the estimates with pandas's round-trip float parser, so a number formats exactly as R would have formatted the double it wrote. Each figure module in `report/figures/` defines `data(dirs)`, the table it plots, and `plot(df)`, the figure drawn from it under the conventions in `.claude/rules/figures.md`, and the runner writes it to `results/plots/`. Slide sets go in the gitignored `reviews/meetings/<date>/`.

`make sync` copies `results/macros/*.tex` and the Illustrator exports in `figures/paper_files/` into `writing/manuscript/`, the article's Overleaf project, which is gitignored and versioned on the Overleaf side; `writing/preregistration/` is frozen with the preregistration and is never written to. The `run-analysis` skill is the procedure for a full run, including `BAYES_FACTORS`.
